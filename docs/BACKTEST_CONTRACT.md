# Industrial Backtest Contract v1

回测必须区分研究口径和交易会计口径，禁止用一个价格字段同时承担两种职责。

## 价格与复权

- `raw_open/raw_high/raw_low/raw_close`：原始可交易价格，只能用于订单、成交、现金和 NAV。
- `economic_open/economic_high/economic_low/economic_close`：经过公司行动连续化的经济价格，用于收益、止损、止盈和技术规则。
- `adj_factor`：复权因子，必须带 `available_time`，并且在决策时点 PIT 可见。
- 复权价格不能直接写入成交账本；发生拆股、送股、分红时，必须先更新股数、成本和现金。
- `adj_factor` 不是公司行动账本。回测必须同时加载除权除息事件：现金分红进入现金流，送股/转增/拆并股进入股数和成本基准；事件必须有 `ex_date` 与 `available_time`。
- 本项目对 Tushare 每 10 股字段转换为每股值：`div_cash / 10` 为现金分红，`1 + (stk_div + stk_bo_rate + stk_co_rate) / 10` 为免费股调整。配股不允许被当作免费送股，必须另建认购现金流模型。

## 事件时序

1. T 收盘读取 `available_time <= T 收盘` 的行情、公司行动和可交易状态。
2. T 收盘生成信号或退出决定。
3. T+1 开盘尝试执行；停牌、涨停买入限制、跌停卖出限制时订单保持未成交并记录原因。
4. 新买入仓位遵守 A 股 T+1，不允许当日卖出。
5. 盘中止损需要独立的日内数据；只有日线数据时，止损只能声明为“收盘触发、次日执行”，不能伪装成盘中止损。

## 止损

止损收益使用经济价格和经济成本基准计算。触发后使用下一可交易时点的原始价格成交，并记录：触发时间、触发价、执行时间、执行价、延迟原因和滑点。

当前日线生产实现的唯一允许模式是 `close_next_session_open`：止损阈值必须使用比例表示（例如 `-0.08` 表示 -8%，不能写成 `-8.0`）。收盘触发、次日开盘执行；跳空、跌停、停牌或缺失行情时，订单保持 `PENDING`，直到成交或在回测结束时以明确原因 `EXPIRED`，禁止静默补成交。

分钟回测支持 `5min/15min/30min/60min`。5 分钟数据按实际数据库中探测到的 `market_stk_mins_5m_b*` 桶数路由，使用 `sha256(ts_code) % bucket_count`；不假设固定 15 或 16 桶。分钟 bar 只能证明价格路径，不能证明逐笔委托队列，因此整根 bar 锁在跌停时一律不成交。

每个订单必须有稳定唯一的 `order_id`，并在订单账本中记录 `decision_session`、`trigger_type`、经济触发价/收益、执行会话、原始成交价、状态和最后一次未成交原因。成交账本通过 `order_id` 与订单账本关联。

统计报告必须同时保留 `economic_return`（复权经济收益）与按原始成交、费用、印花税计算的会计收益。止损统计至少包括止损次数、止损成交的跳空收益和未成交/过期次数；不得用复权价格计算现金、成交额或 NAV。

跳空、跌停、停牌、缺失行情和公司行动必须进入订单状态机，不能静默用收盘价替代成交价。

## 审计不变量

- 现金守恒：现金变化等于成交净额、费用、税费和公司行动现金流之和。
- 股数守恒：成交股数和公司行动调整后，持仓股数可重放。
- NAV 恒等式：`nav = cash + Σ(shares * raw_mark_price)`。
- 每笔订单都有唯一 ID、决策时间、可见数据快照、状态和最终原因。
- 止损触发价、实际成交价和复权因子都必须可追溯。
